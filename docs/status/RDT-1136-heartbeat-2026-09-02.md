## Completed

### ConfirmDialog composition in the shell — destructive desktop flows no longer fire blind

This heartbeat executed the top queued item from the RDT-1130 shell-integration status doc (2026-09-02): **refactor destructive shell flows onto `ConfirmDialog`** (AppInfoModal had already demonstrated the composition pattern).

Three destructive context-menu actions in `Desktop.svelte` previously mutated state instantly, with no confirmation and no feedback:

| Flow | Trigger | Before | After |
|------|---------|--------|-------|
| **Remove from Desktop** | App icon right-click → 🗑️ Remove from Desktop | `hideIcon(app.id)` ran immediately | Danger `ConfirmDialog` ("Remove *Clock* from desktop?") → only on **Remove** does the icon hide |
| **Reset Icon Positions** | Desktop right-click → ↩️ Reset Icon Positions | `resetIconPositions()` wiped custom layout instantly | Danger `ConfirmDialog` warns custom arrangement is lost → **Reset positions** only on accept |
| **Reset Widget Positions** | Desktop right-click → Widgets → ↩️ Reset Positions | `widgetRegistry.resetPositions()` ran instantly | Same danger confirmation pattern |

**Key properties (verified by the O1 ConfirmDialog semantics, tested in `packages/ui`):**
- A destructive action can **never** fire from a dismissal path — Escape, backdrop click, close X and Cancel fire `onclose` only; `onconfirm` (the only path that mutates) fires from the danger button.
- Confirm dialogs mount at `z-[9999]` — above the window stack, same layer as the shell's Dialog/Toast layering work from RDT-1130.
- Focus moves to the **Cancel** button on open (safe default: Enter can't accidentally confirm destruction).
- The context menu closes when a confirmation is armed, so no stale menu lingers under the modal backdrop.

**Post-action feedback:** each confirmed action now surfaces an `info` toast via the O1 `pushToast` channel added in RDT-1130 ("Removed from desktop" / "Icon positions reset" / "Widget positions reset") — destructive changes no longer happen silently.

### Architecture: extracted pure logic for testability

Desktop.svelte has no render-test precedent (it pulls in the window manager, taskbar, widget registry, auth, keyboard shortcuts — too heavy to mount in jsdom). To keep the new behavior tested, the decision/dispatch logic lives in a new pure module:

- **`src/lib/shell/desktop-confirmations.ts`** — `DesktopConfirmAction` discriminated union, `confirmMeta(action)` (title/description/confirm-label copy) and `executeConfirmedAction(action, deps)` (dispatch to exactly one destructive dependency + an info toast).
- **`Desktop.svelte`** stays thin glue: `requestConfirm(action)` arms `pendingConfirm`; the mounted `<ConfirmDialog>` calls `executeConfirmedAction` with the real shell deps (`desktopIconsRef`, `widgetRegistry`, `pushToast`).
- **`src/lib/shell/desktop-confirmations.test.ts`** — 9 tests: confirmation copy per action kind, and dispatch isolation (confirming one action never touches the other destructive deps), plus an `it.each` guard that every action kind has copy.
